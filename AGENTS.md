## Working rules
- First identify the user's requested outcome, the governing project, and the existing application or repository. Reuse this repository when its scope matches.
- Read README.md, docs/WORKSPACE.md, relevant source files, and any applicable nested AGENTS.md before changes. Check current files and workflows rather than treating old summaries as execution evidence.
- Use ChatGPT for discussion and decisions, Work for research and documents, and Codex for code, tests, and repository work. Choose by the deliverable; a product name or skill name is not authorization to create another product.
- Preserve original work. Do not delete chats, files, repositories, or projects without explicit user authorization.
- Never place passwords, API keys, or tokens in source, documentation, or logs.
- Sending email or publishing LinkedIn content requires the user's approval of the specific content. Organizing this workspace does not authorize starting campaigns or workflows.
- Preserve existing audiences. Online access does not imply public publication.
- Finish a meaningful code task with appropriate verification and a brief factual handoff: changed files, actual checks, open issues, next step. Maintain docs/WORKSPACE.md when the scope or status materially changes.
- Newer explicit user instructions override older summaries. Do not claim automatic access to other chats, projects, or local computers.
